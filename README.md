# NeoMuse — Smart Museum Management System

**NeoMuse** — современная веб-платформа для автоматизации внутренних бизнес-процессов музея:
управление экспонатами, онлайн-бронирование билетов, планирование экскурсий, аналитика
посещаемости, генерация отчётов и ролевое разграничение доступа.

Интерфейс системы полностью на **русском языке**. Код, комментарии и API — на английском.

## 🧰 Технологический стек

## 👥 Роли пользователей

1. **Администратор (Admin)** — полный доступ: пользователи, аналитика, отчёты, все данные музея.
2. **Менеджер (Manager)** — экспонаты, билеты, экскурсии, операционная статистика.
3. **Гид (Guide)** — просмотр назначенных экскурсий, изменение их статуса, списки участников.
4. **Посетитель (Visitor)** — каталог экспонатов, бронирование билетов, запись на экскурсии,
   просмотр собственных бронирований.

## ✨ Возможности

- 🔐 Регистрация, вход, JWT-аутентификация, ролевой доступ, защищённые маршруты
- 🏛 Каталог экспонатов: CRUD, поиск, фильтрация, кэширование популярных экспонатов в Redis
- 🎟 Билеты: бронирование, автоматический расчёт цены, QR-код, фоновые уведомления
- 🗺 Экскурсии: планирование, назначение гида, запись посетителей, защита от овербукинга
- 📊 Аналитический дашборд с кэшированием статистики в Redis
- 📑 Асинхронная генерация отчётов (CSV) через Celery
- 🤖 Интеграция с Telegram Bot API (с безопасным mock-режимом)
- 🪝 Webhook-эндпоинт для Telegram

## 🚀 Запуск локально

```bash
# 1. Клонировать репозиторий и перейти в каталог
cd neomuse

# 2. Создать виртуальное окружение и установить зависимости
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 3. Создать файл окружения
cp .env.example .env

# 4. (опционально) применить миграции Alembic
alembic upgrade head
# При первом запуске таблицы и начальные данные создаются автоматически.

# 5. Запустить приложение
uvicorn app.main:app --reload
```

Приложение будет доступно на http://localhost:8000

Для фоновых задач (отчёты, уведомления) запустите Redis и Celery-воркер:

```bash
redis-server
celery -A app.core.celery_app.celery_app worker --loglevel=info
```

> Если Redis недоступен, приложение продолжает работать: кэш отключается,
> а отчёты генерируются синхронно. Telegram работает в mock-режиме (логирование).

## 🐳 Запуск через Docker

```bash
docker compose up --build
```

Поднимаются три сервиса: `web`, `redis`, `celery_worker`.
База SQLite и каталог отчётов хранятся в монтируемых volume.

Приложение: http://localhost:8000 · Swagger: http://localhost:8000/docs

## 🔧 Переменные окружения

См. `.env.example`:

| Переменная | Описание |
|------------|----------|
| `SECRET_KEY` | Секрет для подписи JWT |
| `JWT_ALGORITHM` | Алгоритм подписи (HS256) |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | Время жизни токена |
| `DATABASE_URL` | Строка подключения к БД |
| `REDIS_URL` | URL Redis для кэша |
| `CELERY_BROKER_URL` | Брокер Celery |
| `CELERY_RESULT_BACKEND` | Хранилище результатов Celery |
| `TELEGRAM_BOT_TOKEN` | Токен Telegram-бота (пусто → mock-режим) |
| `TELEGRAM_CHAT_ID` | ID чата для уведомлений |
| `DEBUG` | Режим отладки |

> Не коммитьте реальные секреты. `.env` добавлен в `.gitignore`.

## 🏗 Архитектура проекта

```
neomuse/
  app/
    main.py                 # точка входа FastAPI
    web.py                  # серверные HTML-страницы (Jinja2)
    schemas.py              # Pydantic-схемы
    core/                   # config, security, cache, celery
    db/                     # database, models, init_db (seed)
    api/
      deps.py               # зависимости (auth, роли)
      routes/               # auth, users, exhibits, tickets,
                            # excursions, analytics, reports, webhooks
    services/               # бизнес-логика (telegram, reports,
                            # analytics, tickets, cache)
    templates/              # Jinja2-шаблоны (UI на русском)
    static/                 # CSS/JS
    tests/                  # Pytest
    reports/                # сгенерированные CSV-отчёты
  alembic/                  # миграции
  Dockerfile, docker-compose.yml
  requirements.txt, .env.example
  .github/workflows/ci.yml
```

Принципы: разделение слоёв (роуты → сервисы → модели), валидация через Pydantic,
обработка ошибок, код, готовый к переходу на PostgreSQL (вся специфика SQLite
изолирована в `database.py`).

## 🧩 Redis, Celery, Docker, CI/CD

- **Redis** используется как кэш (популярные экспонаты, статистика дашборда с TTL)
  и как брокер/бэкенд результатов для Celery.
- **Celery** выполняет фоновые задачи: генерация отчётов и отправка уведомлений,
  чтобы не блокировать HTTP-запросы.
- **Docker / Docker Compose** разворачивают всё приложение одной командой
  (`docker compose up --build`) с изолированными сервисами.
- **CI/CD (GitHub Actions)** при каждом push и pull request устанавливает зависимости,
  запускает линтер (ruff), проверяет импорт приложения и прогоняет тесты Pytest.
